# cost-reduction — VitaStore

Проектная работа 3 курса **«Архитектор решений»**.
Кейс: федеральная дрогери-сеть **VitaStore** — 500+ магазинов, рост через M&A,
цель — снизить TCO магазина на 40% и сократить открытие новой точки с 2 недель до 5 дней.

## Контекст

- **Драйвер:** cost reduction. Причина — операционные расходы на интеграцию купленных магазинов
  и поддержку локальной ИТ-инфраструктуры.
- **AS-IS:** в каждом магазине «толстый» кассовый клиент и локальная БД (MS SQL / PostgreSQL);
  в HQ — SAP ERP, Promo Engine, Smart Fulfillment.
- **Проблемы:** ручной маппинг номенклатуры (до 2 недель, 15% ошибок), более 500 локальных серверов
  с платными лицензиями, разнородные платёжные терминалы, зависимость от офлайн-кассы,
  ночной обмен файлами вместо real-time.
- **Целевое состояние:** Cloud POS (тонкий клиент), локальных серверов нет, hardware abstraction
  для терминалов, офлайн-режим, автоматический SKU Matching с ИИ.

## Architecture Work Brief (SAW)

| Раздел | Содержание |
|---|---|
| **Бизнес-цели и драйверы** | Снизить TCO магазина на 40%; сократить открытие точки с 2 недель до 5 дней. Драйвер — cost reduction, не технологии |
| **Границы (scope)** | Магазинные операции, касса, интеграция номенклатуры, локальная инфраструктура, онбординг. **Вне границ функционально:** SAP-модули финансов и HR, Smart Fulfillment, Promo Engine — остаются как системы, меняется размещение (облако) и способ интеграции |
| **Ограничения** | Бюджет и срок 3 месяца на первый этап; фискальные требования и ОФД; разнородные терминалы (Сбер, Альфа, Ingenico, Verifone); офлайн-продажи обязательны; 152-ФЗ и PCI DSS |
| **Стейкхолдеры** | Спонсор — финансовый директор; ИТ-дирекция; Store Ops; Data Integration; ИБ; магазины |
| **Артефакты** | Карта возможностей и sourcing, BPMN TO-BE, AS-IS C4 и HLD, TCO |
| **Критерии успеха** | TCO −40%, онбординг ≤5 дней, ошибки маппинга ≤1%, локальных серверов — 0 |

## Стейкхолдеры (влияние — интерес)

| Стейкхолдер | Влияние | Интерес | Стратегия |
|---|---|---|---|
| Финансовый директор (спонсор) | Высокое | Высокий | Управлять внимательно: каждое решение — в деньгах |
| ИТ-дирекция | Высокое | Высокий | Управлять внимательно: стек, интеграции, эксплуатация |
| Служба ИБ | Высокое | Низкий | Поддерживать удовлетворённость: право вето, безопасность платежей |
| Store Ops | Среднее | Высокий | Информировать: поддержка и инциденты |
| Data Integration | Среднее | Высокий | Информировать: маппинг и качество данных |
| Магазины (продавцы) | Низкое | Высокий | Информировать и обучать |
| Департамент M&A | Высокое | Средний | Держать в курсе: сроки открытия точек |

## Структура

```
Task1/   Аудит и карта бизнес-возможностей, Buy vs Build
Task2/   Целевой процесс онбординга магазина (BPMN + автоматизация)
Task3/   Целевая облачная архитектура (AS-IS C4, HLD, offline-режим)
Task4/   Расчёт TCO и ROI
```

## Задания

| # | Задание | Результат |
|---|---|---|
| 1 | Аудит и карта возможностей | Heatmap L1–L2, матрица Sourcing Strategy |
| 2 | Онбординг магазина | BPMN 2.0 TO-BE, точка верификации |
| 3 | Облачная архитектура | AS-IS C4, HLD с HAL, стратегия офлайн-синхронизации |
| 4 | Экономика | TCO за 3 года, ROI, break-even |

## Целевые показатели

| Показатель | AS-IS | TO-BE |
|---|---|---|
| TCO 100 магазинов за 3 года | 163,4 млн ₽ | 92,9 млн ₽ (−43%) |
| Открытие магазина | 14–21 день | ≤ 5 дней |
| Локальные серверы | 500+ | 0 |
| Ручной маппинг SKU | ~80% ассортимента | ≤ 10% (только спорные) |
